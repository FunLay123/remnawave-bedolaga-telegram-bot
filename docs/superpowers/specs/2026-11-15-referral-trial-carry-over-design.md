# Перенос реферального остатка триала — дизайн

## Цель

При первой покупке любого тарифа в схеме `REFERRAL_REWARD_SCHEME=days_only` сохранять только неиспользованные реферальные дни. Базовый бесплатный триал и уже прошедшая часть реферальных дней не переносятся.

Пример: базовый триал 3 дня, реферальные награды +20 дней. Покупка на следующий день переносит 20 дней; покупка через 5 дней — около 18; после окончания всего срока — 0.

## Зачем

Сейчас базовый триал и реферальные продления складываются в один `end_date`. При покупке либо переносится весь остаток, либо он весь сгорает. Пользователь не должен терять заработанные дни только потому, что решил оплатить тариф.

## Правила

- Поведение включается только для `days_only`; новой env-настройки нет.
- Перенос разрешён при покупке любого тарифа. Сейчас доступен один тариф: отдельные multi-tariff сценарии не расширяем.
- Переносится `max(0, end_date - max(now, base_trial_end_date))` с точностью до секунд, а не округлёнными сутками.
- Реферальный бонус приглашённому, уже включённый в создаваемый триал, относится к переносимому хвосту.
- Реферальные награды продолжают продлевать триал без установки `is_trial=False` и не меняют базовую дату.
- После настоящей покупки подписка становится платной по существующим правилам; повторного переноса хвоста при следующих продлениях нет.
- Прочие схемы реферальных наград и правила `TRIAL_ADD_REMAINING_DAYS_TO_PAID` / `TARIFF_SWITCH_RESET_FREE_DAYS` для них не меняются.
- Истёкший до покупки хвост не восстанавливается.
- Покупка не должна менять существующие правила трафика, устройств, сквадов, автоплатежа и идентичности пользователя RemnaWave.

## Реализация

Добавить nullable `subscriptions.base_trial_end_date`. При создании или повторной активации триала сохранять срок без реферального бонуса приглашённого. Не изменять это поле в `add_reward_days` и `grant_reward_days`.

Общий помощник вычисления остатка используется всеми путями покупки текущего единственного тарифа: центральное продление/конвертация, revive истёкшей подписки и прямые bot/Mini App/cabinet расчёты. Конверсия триала стартует от момента покупки; вычисленный реферальный остаток добавляется один раз.

Для старых строк с `base_trial_end_date IS NULL` историю не реконструируем: сохраняем прежнее поведение `should_carry_trial_remaining_days()`.

## Не входит

- Перенос бесплатных дней уровневой реферальной схемы.
- Новые multi-tariff сценарии и отдельный перенос с нескольких одновременно существующих триалов.
- Перенос админских, промокодных или конкурсных дней отдельно от реферальных.
- Изменение размеров наград, порогов первой покупки и интерфейса партнёрки.
- Новый признак «бонусного платного пользователя».
- Автоматический backfill базовой даты по старым ledger-записям.

## Критерии приёмки

1. В `days_only` триал 3 дня +20 бонусных при немедленной покупке 30 дней даёт 50 дней, а не 53.
2. Тот же результат получается при покупке единственного тарифа через бот, кабинет и центральный CRUD-путь.
3. После окончания базового триала остаётся только неиспользованный хвост; после полного окончания — 0.
4. Повторное продление платной подписки не переносит старый хвост повторно.
5. `add_reward_days` не меняет `is_trial` и базовую дату.
6. Для старой строки без базовой даты и для схемы `levels` поведение остаётся прежним.
