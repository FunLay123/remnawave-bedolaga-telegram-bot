# Юридические документы и новое меню поддержки — дизайн

**Дата:** 2026-10-30
**Статус:** на ревью

## Цель

Добавить боту юридический блок для модерации Heleket и обычной работы сервиса:

- публичная оферта;
- политика возвратов;
- политика конфиденциальности;
- правила сервиса;
- видимый контакт поддержки.

Документы должны приниматься при входе (оферта и правила), быть доступны из бота и легко
редактироваться в коде. Меню «Техподдержка» переделывается под минимализм; кнопка поддержки
ведёт на @FunLay123, тикетная система остаётся в коде, но убирается из меню.

## Решения

- Документы хранятся в коде: HTML-файлы в `app/legal_documents/`, без админки и без миграций.
- Документы и новые экраны — на русском; для остальных языков тексты падают в русский дефолт.
- При входе обязательны только **оферта** и **правила**. Возвраты и конфиденциальность доступны,
  но не блокируют регистрацию.
- Раздел «Документы» доступен из меню поддержки.
- Старый раздел «Инфо» скрыт в боте пользователя — не трогаем.
- Тикетные кнопки убираем из меню поддержки; обработчики тикетов и старые callback’и не удаляем.
- Контакт в документах и на кнопке — только `@FunLay123`.
- Реквизиты исполнителя — плейсхолдеры, заполняются владельцем до подачи в Heleket.
- Условия возврата — до активации ключа; после активации возврат только при технической
  неисправности по вине исполнителя.

## UX

### Меню поддержки

Callback остаётся `menu_support`. Сообщение текстовое.

```
<tg-emoji emoji-id="5359415772844152891">🛠</tg-emoji> <b>Техподдержка</b>

<blockquote>Документы и условия сервиса — ниже.</blockquote>
```

Кнопки:

| Кнопка | Данные | Стиль |
|---|---|---|
| Документы | callback `legal_docs`, иконка `5359415772844152891` | нет |
| Написать в поддержку | URL `https://t.me/FunLay123`, иконка `5332588449335628124` | `primary` |
| Назад | callback `back_to_menu` | нет |

Строку «Написать нам: @FunLay123» в тексте не показываем — контакт только на кнопке.
Экран рендерится текстом (`force_text=True`), чтобы в режиме логотипа не превращаться в фото.

### Вход

После выбора языка вместо старых «правила → политика конфиденциальности» показывается один экран.

```
<tg-emoji emoji-id="5359415772844152891">📄</tg-emoji> <b>Перед началом</b>

Чтобы пользоваться сервисом, примите:
• Публичную оферту
• Правила сервиса
```

Кнопки:

| Кнопка | Действие |
|---|---|
| Публичная оферта | открыть документ `offer`, назад — на экран входа |
| Правила сервиса | открыть документ `rules`, назад — на экран входа |
| Политика возвратов | открыть документ `refund`, назад — на экран входа |
| Политика конфиденциальности | открыть документ `privacy`, назад — на экран входа |
| Принимаю | callback `legal_accept`, иконка `5460980668378931880`, `primary` |

`Принимаю` записывает согласие с `public_offer` и `service_rules` и продолжает регистрацию.
`SKIP_RULES_ACCEPT=true` по-прежнему пропускает весь юридический шаг; согласие тогда не пишется.

### Раздел «Документы»

```
<tg-emoji emoji-id="5359415772844152891">📄</tg-emoji> <b>Документы</b>

<blockquote>Оферта, возвраты, конфиденциальность и правила сервиса.</blockquote>
```

Кнопки в порядке:

1. Публичная оферта — `legal_doc:offer:1:hub`
2. Политика возвратов — `legal_doc:refund:1:hub`
3. Политика конфиденциальности — `legal_doc:privacy:1:hub`
4. Правила сервиса — `legal_doc:rules:1:hub`
5. Назад — `back_to_menu`

### Экран документа

```
<b>Публичная оферта</b>
Редакция от 30.10.2026

<текст документа>
```

- HTML преобразуется в Telegram-разметку тем же механизмом, что правила/оферта сейчас.
- Длинный текст режется на страницы; навигация `‹ 1/3 ›`.
- Назад ведёт в хаб или на экран входа — в зависимости от того, откуда открыли.
- Шапка без кастомного эмодзи; заголовок документа выделен жирным.

## Поток

1. Пользователь выбирает язык (или язык уже известен).
2. Если `SKIP_RULES_ACCEPT=false`, на месте старого шага правил показывается экран «Перед началом».
3. Пользователь может открыть любой из четырёх документов; кнопка «Назад» возвращает на вход.
4. «Принимаю»:
   - ставит в FSM `legal_accepted=True`;
   - удаляет экран входа;
   - продолжает старый путь регистрации (реферальный код / завершение).
5. После создания/восстановления пользователя `complete_registration` и
   `complete_registration_from_callback` записывают `legal_consents`:
   - `public_offer`, `service_rules`;
   - `source='bot_registration'`;
   - запись не должна ронять регистрацию.
6. После входа документы доступны из «Техподдержка» → «Документы».

## Юридические тексты

Русский язык, HTML с Telegram-тегами. Плейсхолдеры:

`[ИП Фамилия И.О.]`, `[ИНН]`, `[ОГРНИП]`, `[адрес]`, `[email]`, `[юрисдикция]`.

### Оферта

- Исполнитель и реквизиты.
- Предмет: доступ к VPN-сервису, выдача ключа/ссылки.
- Акцепт оферты и момент заключения договора.
- Срок подписки, продление, ограничения устройств/трафика.
- Цена, порядок оплаты, платёжные провайдеры.
- Права и обязанности сторон.
- Ответственность и ограничение ответственности.
- Возвраты — со ссылкой на политику возвратов.
- Форс-мажор.
- Изменение условий.
- Контакты: @FunLay123.

### Политика возвратов

- Возврат до активации ключа/ссылки.
- После активации возврат не производится, кроме технической неисправности по вине исполнителя.
- Как подать заявку: @FunLay123.
- Срок рассмотрения и способ возврата.
- Исключения и злоупотребления.

### Политика конфиденциальности

- Какие данные собираются: Telegram ID, username, платёжные и технические данные.
- Цели обработки.
- Кому передаются: платёжные провайдеры, панель Remnawave.
- Сроки хранения.
- Права пользователя.
- Контакт: @FunLay123.

### Правила сервиса

- Допустимое использование.
- Запреты: перепродажа доступа, злоупотребления, торренты и т.п.
- Блокировка за нарушения.
- Ответственность пользователя.
- Изменение правил.
- Контакт: @FunLay123.

## Совместимость и легаси

- Старые `PrivacyPolicy`, `PublicOffer`, `ServiceRule` и админские редакторы не удаляем;
  пользователь их больше не видит.
- Старые `process_rules_accept` / `process_privacy_policy_accept` оставляем для старых сообщений,
  но новый вход их не вызывает.
- Админский текст «о поддержке» остаётся в коде настроек, но новое меню его не использует:
  текст меню фиксированный.
- Тикетные обработчики, `create_ticket`, `my_tickets` остаются; из меню поддержки убираются.
- Старые сообщения с тикетными кнопками продолжают работать.

## Тесты

- Вход: показ экрана, открытие оферты/правил, возврат, «Принимаю» продолжает регистрацию.
- `SKIP_RULES_ACCEPT=true` пропускает экран и не пишет согласие.
- Запись `legal_consents` для `public_offer` и `service_rules` после создания пользователя.
- Поддержка: новая клавиатура, URL @FunLay123, отсутствие тикетных кнопок.
- Документы: все четыре открываются, пагинация, назад в хаб/вход.
- Старые ticket-callback’и не сломаны.
- Структурная справка и ruff.

## Вне scope

- Админка для редактирования документов.
- Новые таблицы и миграции.
- Автоматические возвраты.
- Удаление тикетной системы.
- Изменение скрытого раздела «Инфо».
- Юридическая экспертиза текстов (нужна отдельно).

## Риски

- Плейсхолдеры реквизитов обязательны к заполнению до подачи в Heleket.
- Условия возврата «до активации» могут требовать проверки юристом.
- Heleket проводит KYC и смотрит на реальность проекта; документы — только часть.
- @FunLay123 должен быть публичным и рабочим.
